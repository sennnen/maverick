# M2 — Mock second device

M2 exists to test an abstraction, and the honest way to test an abstraction is to try to break it. After M1 the connector abstraction (manifest plus `DeviceCodec`) has seen exactly one device, which means it has been shaped to fit that device and nothing has yet forced it to prove it is general. So we build a second device that is fake, and deliberately awkward: a different start-of-frame byte, big-endian lengths where WHOOP is little-endian, a one-byte CRC trailer where WHOOP carries four, a delta-encoded stream that needs decode memory across frames, and a per-device anchor that must survive in the key-value store between sessions. Each of those differences targets an assumption the WHOOP formats could have quietly baked into the core.

The exit condition is hard and it is the whole point: the mock streams through the pipeline and out to a snapshot with zero edits to the pipeline crates. Precisely: no source change under `core/crates/{mav-model, mav-frame, mav-codec, mav-timeline, mav-sqi, mav-feature, mav-analytic, mav-store, mav-obs, mav-engine, mav-ffi}/src`. The one permitted touch is generic plumbing in `mav-replay` (the composition root) to load a connector by manifest path, and that plumbing may not name the mock or any other device. If making the mock work seems to require a real core edit, the milestone has done its job by failing early: stop, write up what the abstraction could not express, and take it to an ADR. Do not work around it.

The mock is designed with M3 in mind: it declares `HeartRate` only and deliberately lacks `RrInterval`, because M3 uses a device without RR to prove that capability negotiation hides recovery rather than computing garbage.

Packets are in dependency order. The ownership rules from M0 and M1 hold.

## Packet M2-P1: Mock wire format, manifest, capture fixtures

**Owns:** `connectors/mock/manifest.json`, `connectors/mock/FORMAT.md` (the wire format specification), `fixtures/capture/mock_hr_v1.bin`, `fixtures/capture/mock_hr_resume_v1.bin`, and their provenance READMEs under `fixtures/capture/`.

**Must not touch:** any crate source. This packet is specification and data.

**Contract:** Define the mock wire format in `FORMAT.md`, exactly:

- Frame: `[0] = 0x5A` start-of-frame (not WHOOP's `0xAA`), `[1..=2] = payload length` u16 **big-endian** (payload bytes only, excluding header and trailer), `[3..] = payload`, and a single trailing byte `CRC-8` (polynomial `0x07`, init `0x00`, the same function `mav-frame` already ships) computed over the payload. No padding. Total frame length is `payload length + 4`.
- Payload: `[0] = record type`, `[1] = sequence` u8, `[2..] = body`.
- Record type `0x00`, keyframe: body is `timestamp` u32 big-endian (seconds), then `base_hr` u8, the absolute heart rate in device units.
- Record type `0x01`, delta: body is `timestamp` u32 big-endian, then `delta` i8, the signed change from the previous decoded heart rate. A delta record is undecodable without knowing the previous value, which is the designed-in statefulness.
- Device units to bpm: `bpm = device_units + anchor`, where `anchor` is a small per-device calibration offset carried in the keyframe payload's final byte (`anchor` i8) and persisted to the per-device key-value store. This mirrors the WHOOP 4.0 learned skin-temp anchor, the exact case that justified giving the `DeviceCodec` a KV handle in the first place.

The manifest declares the mock's identity, its capability set (exactly `HeartRate`, no `RrInterval`), and its frame parameters as far as the manifest schema can express them; where the schema cannot express something (the big-endian length, the CRC-8 trailer, the delta decode), `FORMAT.md` says so explicitly, because those are precisely the things the codec exists to hold and the record of what fell to code is raw material for the P4 write-up.

Two capture fixtures: `mock_hr_v1.bin` opens with a keyframe and continues with deltas, decoding to a known HR series; `mock_hr_resume_v1.bin` contains **only** delta records, decodable solely by a codec that has the previous value and anchor warm in its KV store. Both are generated through `skills/golden-fixtures` with expected-output JSON alongside, never hand-edited.

**Tests first:** this packet's assertions live in P2, which consumes the fixtures. Here, only: `mock_manifest_loads` — the manifest deserialises through the `mav-codec` types with the capability set asserted as exactly `HeartRate`.

**Exit:** `cargo test -p mav-codec` (manifest load test), `tools/check_docs.sh` (FORMAT.md and fixture READMEs cross-reference cleanly).

**Notes:** Every deliberate difference from WHOOP is listed in `FORMAT.md` with one line on which assumption it targets (SOF value, length endianness, CRC width and placement, padding, stateless decode, absolute encoding). That list becomes the checklist for the P4 doc section.

**Status: format spec written; a blocking finding surfaced, exactly as intended.** `connectors/mock/FORMAT.md` is written with the full wire spec and the deliberate-differences checklist. Writing it surfaced the finding M2 exists to find: the M1 design frames bytes in the core reassembler keyed by a closed `frame.wire_format` enum of `gen4`/`gen5` and hands the codec an already-reassembled `RawFrame`, so a device whose framing is neither gen4 nor gen5 cannot be expressed at all, and the manifest cannot even load with an honest wire format. Per the M2 preamble this is the abstraction failing early, not a thing to work around, and the resolution is recorded in [ADR-012](../../adr/ADR-012.md): frame parameters become manifest data and the reassembler becomes description-driven, with gen4/gen5/mock all as configurations. The manifest, the fixtures, and the `mock_manifest_loads` test are therefore blocked on the ADR-012 refactor and land with it; the rest of the mock (the delta decode and the anchor) is genuine codec work and is unaffected.

## Packet M2-P2: Mock codec crate

**Owns:** the new crate `connectors/mock/codec/` in full (its `Cargo.toml` and `src/`), plus the entry adding it to the workspace members in `core/Cargo.toml` (a membership line only; nothing else in that file).

**Must not touch:** any `core/crates/*/src` file. The codec may depend on `mav-model`, `mav-frame`, and `mav-codec` only; `tools/check_deps.py` fails the build if it reaches further, and `docs/architecture.md` gains the mock codec's edges as part of this packet only if the generic codec rule does not already cover them.

**Contract:** Implement `DeviceCodec` for the mock. Because the trait hands the codec raw bytes and asks for frames and samples back, the codec owns its own framing: scan for `0x5A`, read the big-endian length, verify the CRC-8 trailer (calling `mav-frame`'s existing CRC-8 function, not a reimplementation), resynchronise on garbage, and bound frames at the same 8192-byte cap the core uses. Decode is stateful: a keyframe sets the current value and writes both the value and the anchor to the per-device KV store; a delta record applies its signed change to the current value; a delta arriving with a cold state loads the persisted value and anchor from the KV store, and if the store is also cold the record is rejected with a `Decode`-category `MavError` code and reason (never a guess, never a silent drop). Output is `HeartRate` `RawSample`s in bpm with the anchor applied, carrying device timestamps, exactly the shape the untouched pipeline already accepts from the whoop5 path.

**Tests first:**
- `frames_mock_format_from_fixture` — the codec extracts the expected frames from `mock_hr_v1.bin`, including a leading-garbage resync case.
- `rejects_bad_crc8_trailer` — a corrupted trailer byte yields a rejection with the expected error code and no emitted frame.
- `keyframe_then_deltas_decode_to_series` — `mock_hr_v1.bin` decodes to the exact HR series in its expected-output JSON.
- `cold_delta_without_kv_is_rejected` — feeding only delta records to a codec with an empty KV store produces rejections with the expected code, and zero samples.
- `warm_kv_resumes_delta_decode` — after decoding `mock_hr_v1.bin` (which persists state), a fresh codec instance over the same KV store decodes `mock_hr_resume_v1.bin` to its expected series.
- `anchor_is_applied_and_persisted` — the decoded bpm equals device units plus the keyframe's anchor, and the anchor read back from the KV store matches.

**Exit:** `cargo test -p mock-codec` (or the crate's chosen name), `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --check`, `tools/check_deps.py`.

**Notes:** The warm-resume test is the one that earns this milestone its keep: it proves the per-device KV handle in the trait is genuinely load-bearing and not decoration. If you find yourself wanting a hook the trait does not offer, that is a finding, not an obstacle — record it and escalate per the M2 preamble.

**Status: blocked on ADR-012.** The mock codec's decode logic (stateful delta decode, anchor learned into the KV store, cold-delta rejection) is ready to write and is unaffected by the finding, but its framing half depends on the description-driven reassembler from ADR-012, and its manifest cannot load until then. This packet lands with the ADR-012 refactor.

## Packet M2-P3: End to end through the untouched pipeline

**Owns:** the generic connector-loading plumbing in `core/crates/mav-replay/src/` (load a connector by manifest path, register it with the `mav-codec` registry at startup), `fixtures/snapshot/mock_hr_v1.json`, and the parity-harness fixture entries in `apps/ios/` and `apps/android/` (the fixture id and its known-good hash added to the existing M1 test lists).

**Must not touch:** any pipeline crate source. The `mav-replay` change is the single permitted core touch, and it must be device-agnostic: no string `"mock"`, no mock-specific branch, nothing that would need editing again for device number three.

**Contract:** `mav-replay` gains a flag or argument taking a manifest path (and codec, resolved through the registry), so any connector present in the repository can drive a replay without code changes. Running the mock capture through it exercises the full pipeline: codec framing and decode, SQI plausibility scoring, timeline insert, store, HR feature, snapshot — every stage downstream of the codec running the identical code that served whoop5 in M1. The canonical snapshot for `mock_hr_v1` is fixed in `fixtures/snapshot/mock_hr_v1.json`, `run_fixture("mock_hr_v1")` returns its canonical JSON and hash, and both platform parity harnesses assert that hash exactly as they do for the whoop5 fixture.

**Tests first:**
- `replay_mock_reproduces_snapshot_hash` — replaying `mock_hr_v1.bin` through the manifest-path flag yields the canonical hash, equal to `run_fixture("mock_hr_v1")`.
- `mock_snapshot_walkback_resolves` — the mock snapshot's provenance ids walk back through feature, samples, and frames to the raw bytes, proving observability held for a device the pipeline had never seen.
- `capability_set_omits_rr` — the availability set computed for the mock device contains `HeartRate` and does not contain `RrInterval` (the seed of M3's negotiation proof).
- iOS and Android: `parity_mock_hr` — both simulators return the identical known-good hash.

**Exit:** `cargo test --workspace`, both platform parity tests green on `mock_hr_v1`, `tools/check_docs.sh`, `tools/check_deps.py`.

**Notes:** If any stage between decode and snapshot needed an edit to accept the mock's samples, the samples were not really the frozen `mav-model` shape and something upstream cheated; treat it as a P4 finding. The parity assertion matters here for the same reason it did in M1: it proves the second device did not introduce platform-dependent behaviour anywhere.

## Packet M2-P4: "What the abstraction survived", and the no-edit audit

**Owns:** the "What the abstraction survived" section in `docs/connectors.md`, and the M2 retro notes in this file.

**Must not touch:** anything else.

**Contract:** Verify the exit condition mechanically and write down what was learned. The audit: diff the M2 work against the last M1 commit and confirm the only changes under `core/` are the workspace-membership line from P2 and the device-agnostic replay plumbing from P3 — record the exact diff command used and its output summary in the doc section. The write-up walks the deliberate-differences checklist from `FORMAT.md` difference by difference: what the manifest expressed, what fell to the codec, what the per-device KV store had to carry, and anything the abstraction could not express cleanly (each such item either got an ADR or a written justification for why it is acceptable). This section is the reference for whoever adds device number three, and for the cloud connector in M7, which will lean on the same claim that the pipeline does not care where samples come from.

**Tests first:** none; this packet is verification and prose. The audit diff standing empty (modulo the two permitted touches) is its assertion.

**Exit:** `tools/check_docs.sh`; the audit diff recorded; the section merged.

**Notes:** Be blunt in the write-up. An abstraction write-up that reports only success is suspicious for the same reason an always-green test is; the parts where the manifest schema ran out and code took over are the valuable content.

## M2 exit

M2 is done when the mock capture streams through the pipeline to a snapshot with byte-identical hashes on both platform harnesses, the audit diff shows no pipeline-crate source edits beyond the two permitted device-agnostic touches, and the "What the abstraction survived" section is merged into `docs/connectors.md`. This file then moves to `docs/plans/completed/M2.md` with the usual retro: what surprised us, what drifted, and which doc fixes were filed.
