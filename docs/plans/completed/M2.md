# M2 — Connector framing hardening

M2 began as a proposal to build a fake second device. The useful part happened before that device
existed: specifying a wire format unlike WHOOP exposed a closed framing assumption in the core.
Maverick could describe only `gen4` and `gen5`, so any third framing format required a core edit.

The product does not ship or continue a fake connector. The probe ended when it found the
architectural fault; the fault was fixed under ADR-012, and the fake manifest, codec plan, and
integration test were removed.

## Work completed

- ADR-012 made frame parameters manifest data: start byte, length field, endianness, CRC placement,
  trailer counting, and padding.
- `mav-frame::Reassembler` became description-driven.
- gen4 and gen5 became presets of the same `FrameSpec`.
- `mav-codec::FrameConfig` can resolve a custom frame description.
- `mav-engine` reads the reassembler spec from the manifest rather than matching a closed enum.
- Unit tests exercise a non-WHOOP custom frame spec without creating a pretend device family.
- Every WHOOP frame fixture, fragmentation property, corruption property, and frozen replay hash
  stayed unchanged.

## Exit evidence

M2 exits on the architectural claim, not a mock snapshot:

- a custom start byte, big-endian length, and CRC-8 trailer reassemble through `FrameSpec`;
- a custom manifest frame description validates and resolves;
- gen4/gen5 golden fixtures still reproduce byte-for-byte;
- the M1 replay hash remains stable;
- dependency and documentation gates pass.

## Retro

The probe did its job: it found that framing was code when it should have been data. Continuing into
a fake stateful device would have spent time proving invented behaviour rather than decoding real
hardware. User direction made that trade explicit. The reusable architecture remains; mock product
artefacts do not.
