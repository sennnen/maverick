# ADR-033: Captured waveforms are session capabilities with host-owned experiences

## Status

Accepted.

## Context

Maverick can now decode the WHOOP MG raw analog-front-end stream, including its 100 Hz single-lead
ECG channel. The connector that owns that protocol also supports WHOOP 5.0 hardware without an ECG
electrode. A static connector-manifest capability therefore describes the connector's maximum
authority, but cannot honestly describe the connected device.

The product experience is larger than a transport command. It needs a signal-quality calibration
stage, a bounded recording, deterministic preprocessing, native model inference, an explainability
pass, stored provenance, a readable result, and a downloadable PDF. Putting those screens or
decisions in a connector would duplicate presentation, give an untrusted Wasm artifact authority
over health interpretation, and make the next ECG-capable device require another app feature.

Hardcoding `WHOOP`, `MG`, a serial prefix, or an opcode in the core or either app is equally wrong.
It would reverse ADR-017's device boundary and make an ECG-capable connector added later invisible
until both apps shipped again.

## Decision

Captured waveform support has two declarations and one generic host workflow.

1. The signed manifest declares the connector's **maximum** authority. A manifest-v2 `captures`
   declaration
   names a stream already present in `capabilities`, its unit and sample-rate bounds, and the bounded
   start/stop operations it may translate. Inspection and approval show this declaration before the
   connector runs.
2. The connected session declares **active** streams with the existing
   `ActionBody::DeclareCapabilities`. The host intersects that set with the approved manifest. A
   capture entry is absent until the connector has positively identified hardware that can supply
   it. Unknown hardware fails closed.
3. The FFI exposes the admitted intersection through `connector_capture_capabilities`. Native apps
   render a generic vital row and action from that record. They do not inspect connector ids, model
   names, serial prefixes, or display names.

The host starts and stops a capture with additive semantic connector events:

- `CaptureStart { stream }` asks the connector to make the declared stream flow.
- `CaptureStop { stream }` asks it to stop.

The connector translates those meanings into device commands. The runtime accepts transport writes
caused by these events only when the stream is in the approved `capture/v1` declaration and active
session capability. The host owns the deadline and always sends `CaptureStop` on completion,
cancellation, disconnect, or timeout.

For ECG, the reusable host workflow is:

`unavailable -> calibrating -> recording(30 s) -> analysing -> result | failed`.

Calibration consumes the live waveform and advances only after the shared core reports a continuous
good-quality window. It has a bounded timeout and a candid failure reason. Calibration samples are
not part of the 30-second model record. The result screen contains a text-first interpretation,
confidence, signal quality, rate and timing facts, explainability summary, limitations, and capture
metadata. It intentionally contains no rhythm graph. The rhythm graph appears only in the generated
PDF, which is downloaded or shared rather than embedded as an in-app preview.

Rust owns resampling, recovered filtering, fitting, normalisation, quality scoring, explainability
tensor construction, result interpretation, and provenance. Native owns accelerated inference:
Core ML on iOS and TensorFlow Lite on Android. Native returns bounded tensor outputs to the core;
only the core may turn them into a stored health result.

The first model contract is research-only and provisional:

- input: `FLOAT32 [1, 7680, 1]`;
- source record: exactly 30 seconds; WHOOP MG source rate 100 Hz;
- preprocessing: linear resample to 256 Hz, recovered SOS chain, centred fit to 7,680 samples,
  per-record z-score;
- classes: `N` (sinus rhythm), `A` (atrial fibrillation), `O` (other abnormal rhythm);
- iOS: FP16 Core ML ML Program, minimum iOS 15, deployed only to A13-or-newer app targets;
- Android: FP16-weight TensorFlow Lite with FLOAT32 I/O, minimum Android 10;
- model and filter hashes are recorded in `docs/ml.md` and in every stored result.

The labels are descriptions of model output, not diagnoses. UI and PDF must say that a normal
result does not rule out an arrhythmia, an abnormal result is not a diagnosis, and urgent symptoms
require ordinary medical care rather than another reading.

## Consequences

- WHOOP 5.0 and WHOOP MG may share one connector while only MG exposes ECG. The hardware distinction
  remains connector-private.
- Another connector can add the same ECG experience by declaring the same capture stream and
  implementing two semantic events; neither app gains device-specific code.
- The connector ABI and FFI gain additive records and therefore need canonical Rust, Swift, Kotlin,
  native-author, and Wasm parity fixtures.
- The model is admitted as conversion-consistent and software-regression-tested, not clinically
  validated. It remains visibly provisional until evaluated against independently labelled ECG.
- XAI requires multiple native inference passes. The core produces a bounded ordered tensor set and
  interprets the returned vectors, keeping occlusion policy identical on both platforms.
- A connector cannot create a screen, arbitrary copy, or a dynamic executable control. It can only
  make a host-known capture capability available.
