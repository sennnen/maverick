# ADR-008: Provenance by metadata reference

## Context

Maverick's inspector requirement says that for any metric on screen it must be possible to walk
back: metric to features, features to samples, samples to frames, frames to raw bytes. Something
has to carry that chain. Embedding full provenance in every value would bloat every row and every
FFI crossing; carrying nothing would make the walk-back impossible and leave "which algorithm
version computed this" unanswerable, which is exactly the forensic gap that lets silent corruption
persist.

## Decision

Every sample, feature, and prediction carries a MetadataId, a cheap newtype reference into a
provenance table keyed by that id. The row records the source stream, the quality, the algorithm
id, the algorithm version, and the sample count. Provenance travels by reference; the data lives
once, in the store.

## Consequences

Values stay small while the full chain stays reachable, and the walk-back requirement reduces to
following ids through joins. Version questions become queries: when an algorithm changes, the rows
computed under the old version are identifiable, which is what makes selective recomputation and
honest fixture versioning possible. The costs are an id's worth of overhead on every value and the
rule that no derived value may enter the pipeline without one; a value with no MetadataId is
unattributable by construction, and the pipeline treats that as an error rather than a shrug.
