# ADR-024 — The DailySnapshot contract

Status: accepted.

## Context

The analytics half of the core is built, tested, and reachable from nothing. `mav-analytic` is
roughly five thousand lines with a hundred-odd tests; `mav-feature` and `mav-engine::recompute` are
complete. None of them has a caller.

Meanwhile Android ships its own Kotlin scorers — `IllnessSignalEngine`, `RestScorer`,
`V5HealthSignals`, `CyclePhaseEngine` — and iOS shows empty shims. That breaks two standing rules at
once: Rust owns analytics, and a feature ships on both platforms or on neither. It also means the two
apps cannot agree, because nothing forces them to: there is no shared number for them to agree on.

Nothing can be wired until the record crossing the boundary is frozen, because both platforms and
the engine have to build against the same shape. This ADR freezes it, before the code exists.

## Decision

### The record

`DailySnapshot` is what one `LocalDay` produced. Every field is either a value the core computed or
an explicit statement that it could not:

- the **local day** it describes, and the algorithm versions that produced it;
- **HRV time-domain values** — the admitted analytic (`AnalyticId::TimeDomainHrv`), labelled HRV only
  when computed from RR intervals and PRV when computed from PPG, per `docs/analytics.md`;
- **readiness tier**, where the inputs exist;
- **recovery** and **strain**, each carrying its admission status. `AnalyticId::Recovery` is
  `admitted: false` today, so it travels as a compatibility estimate and is labelled as one; a
  platform may not present it as a Maverick score;
- a **sleep summary**, where a night is present;
- an **availability list**: one `AnalyticAvailability` per `AnalyticId`, carrying
  `UnavailableReason` for everything not served.

The availability list is not optional and not derived by the platform. A card whose analytic is
unavailable renders the core's reason. It never renders a platform-computed substitute — that is the
honesty rule in `docs/platform.md`, and it is the rule the Kotlin scorers currently break.

### Triggers

A snapshot is recomputed on session end, on historical-sync completion, and on an app-driven refresh
(midnight rollover, or on demand). The app supplies the trigger; the core decides what work it
implies, through `AffectedDays`.

### Cache

The existing `RecomputeCache`/`CacheKey`. A cache hit short-circuits recomputation; a day entering
`AffectedDays` invalidates its key. No new caching mechanism.

### Timezone

Rust gets no tzdata dependency. The platforms already have a correct, updated zone database and are
the only place a user's zone is actually known, so they supply **explicit offset spans** over FFI
into the existing `Timezone::new(id, spans)`. `RuntimeConfig.timezone_id` is retained as a label —
it names the zone the spans came from, and it is not used to compute an offset.

This is the one place a platform legitimately feeds a value into an analytic input, and it is
narrow on purpose: a span is a fact about the world, not a judgement about health data.

## Consequences

Both platforms render the same numbers from the same fixture, because there is only one computation.
The Kotlin engines are deleted rather than ported wholesale, and any scorer that cannot pass the
ADR-009 admission bar becomes explicitly unavailable on both platforms rather than silently ported to
one. `CyclePhaseEngine` is the expected casualty: it has no reference and no fixture, so it lands as
unavailable — an accepted, visible regression, decided here rather than discovered later.

Freezing the record before writing the engine is the point of this ADR. The alternative — letting the
shape emerge from whichever platform was wired first — is exactly how the two apps drifted apart in
the codebases this one replaced.
