# ADR-030: Power mode is a host policy the connector obeys

## Status

Accepted.

## Context

A strap and a phone both pay for every notification, every reconnect, and every history offload. The
user has no way to say "I care about battery more than resolution today", and the connectors have no
way to hear it if they did. The knobs that matter are all inside the connector — how often it pulls
the historical offload, which characteristics it subscribes to, whether it opens a raw stream — but
the *policy* is a user preference that belongs to the app.

Two shapes were considered. The host could throttle the transport underneath a connector that knows
nothing about it, or the host could state the policy and let each connector decide what to give up.
Transport throttling is invisible to the connector: it would keep asking for an offload on its own
cadence and keep being starved, which turns a battery setting into a stream of timeouts and retries
that costs *more* power than it saves.

## Decision

Power mode is a **host policy delivered to the connector as an event**, and the connector decides how
to honour it.

- `EventBody::PowerModeChanged { low_power: bool }` (ABI tag 27, additive — old artifacts simply
  never receive it) is delivered on every change, and re-stated on activation and resume **when low
  power is engaged**, so a connector's behaviour is always a pure function of the events it has
  seen. Full power is the connector's own default and is not restated: spending a connector's fuel
  to tell it what it already assumes buys nothing, and a session that never hears the event behaves
  exactly as it did before this ADR.
- A connector in low power **must** keep its primary vitals stream working. Battery is traded from
  the optional edges: diagnostic subscriptions, raw streams, and the *cadence* of history offload.
- The host does not verify what a connector gives up. A connector that ignores the event is correct
  but impolite; the manifest is not the place to police it, because "how much battery" is not
  something the ABI can measure.

The two named levels are deliberate. A continuous "battery budget" number would have to be tuned per
device and per firmware, and neither the host nor the user has the information to set it.

## Consequences

- The setting is one boolean over FFI and one toggle in each app, and it ships on both platforms at
  once, as parity requires.
- Connectors gain a state bit that must survive suspend/restore like any other, so a resumed session
  does not silently return to full power.
- The event is additive: existing signed artifacts stay valid, and the ABI minor is unchanged
  because a connector that has never seen tag 27 behaves exactly as it did before.
- Battery *measurement* is out of scope here. This ADR gives the user a lever and connectors a
  contract; proving how many milliamps it buys needs hardware instrumentation, not a decision record.
