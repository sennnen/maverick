# ADR-029 — An all-integer sample table, indexed by wall time

Status: accepted.

## Context

The v1 `sample` table was `WITHOUT ROWID` with `PRIMARY KEY (device_id, stream, device_time_ns,
seq, value_json)`, where `stream` was a JSON string and `value_json` was a JSON object. Every row
carried both strings inside its own primary key, every lookup compared strings, and every read
parsed JSON per row.

There was no index of any kind. `Store::samples` — documented as "used by the round-trip guarantee
and by tests" — was the production read path: `Spine::compute` called it for every stream, for all
time, to render one day. A sixty-day history view was a hundred and twenty full table scans, and
the cost grew with everything the device had ever recorded.

## Decision

Rebuild `sample` with integer columns only, and index it by the thing reads are actually bounded
by:

```sql
PRIMARY KEY (device_id, stream, device_time_ns, seq, value_tag, value_bits)
CREATE INDEX sample_by_wall ON sample (device_id, stream, wall_time_ns);
```

`StreamKind` and `RejectReason` gain durable integer codes — the declaration index, pinned by a
test that spells out the pairs so a reordering cannot silently relabel stored rows. `RawValue`
encodes as `(tag, bits)`, which is lossless for every width and is the same `key_bits` the timeline
already deduplicates on, so the fast in-memory layer and the durable one now agree on what a
duplicate is by construction.

Reads become windows: `samples_between`, `streams_between`. A `nightly_variability` memo holds one
RMSSD per device, day and interval stream, so a sixty-night look-back reads sixty small rows
instead of re-deriving two months of beats.

The in-memory snapshot cache is deleted with it. It was never invalidated in production — nothing
called `Spine::invalidate` — so a rendered day could outlive the sync that changed it. Recomputing
from an indexed window is cheap enough that the honest answer is to always recompute, and the
snapshot row is only rewritten when it differs.

## Consequences

Storage is a forward-only migration that re-encodes existing rows in Rust, because reshaping a row
means decoding it and SQLite cannot decode our value types; `MIGRATIONS` gains a `Rust` variant for
this and any future data migration.

`AffectedDays`, `CacheKey` and `RecomputeCache` are deleted — with the cache gone, nothing used
them.
