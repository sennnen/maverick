# ADR-011 — Connectors are a separate importable package, not bundled in the app

Status: repository separation retained; folder-manifest import model superseded by
[ADR-017](ADR-017.md).

## Context

A connector teaches Maverick how to talk to one family of device: a `manifest.json` of static wire
facts and, where needed, a small codec crate. WHOOP 4.0 and WHOOP 5.0/MG were first written in the
core repository, under `connectors/`.

Leaving them there conflates two different things. Device support is a moving target that a user
might want to add, update, or remove on its own schedule, and it is exactly the part most likely to
carry facts that are still provisional or wrong. The core is a stable foundation that a device
manifest should never be able to destabilise. If connectors ship inside the app, then adding a device
means shipping a new app, a wrong offset in a manifest rides in a core release, and the app becomes
the home for device-specific code that the whole architecture is trying to keep at arm's length.

## Decision

Connectors live in their own repository, `sennnen/maverick-connectors`, and are imported, not built
in. The app reads connector manifests from that repository (or from a user's local copy); it does not
embed them. The core does not depend on the connectors repository at the crate level, and the
dependency that does exist runs the other way: a connector is validated against the core's `mav-codec`
schema, so `mav-codec` never learns about any specific device.

There is one exception. A generic Bluetooth heart-rate connector for the standard GATT Heart Rate
profile (`0x180D` / `0x2A37`) may ship inside the app as a zero-configuration fallback, because that
profile is an open standard every chest strap and watch implements identically, not a device family.
Anything that decodes a proprietary format is a connector and belongs in the connectors repository.

The core repository keeps no proprietary device connector and constructs any device manifest its own
tests need as an inline fixture rather than reaching into the connectors repository.

## Consequences

Adding, fixing, or removing a device is a change to the connectors repository, with its own release
cadence, and never a core release. The core's tests stay hardware-free and self-contained: the schema,
the codec, and the registry are exercised with inline manifests, and the shipped device manifests are
validated in the connectors repository against `mav-codec`. The boundary from
[ADR-007](ADR-007.md) is now physical as well as logical, which makes the "a connector cannot reach
into the core" rule something the repository layout enforces, not just the type system.

The cost is that developing the first real vertical slice against a WHOOP capture needs the
connectors repository checked out alongside the core, and the core's own CI cannot validate a shipped
device manifest end to end (that check belongs to the connectors repository). Both are acceptable:
the slice is a development activity, and the manifest's home is the right place to test it.
