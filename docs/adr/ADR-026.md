# ADR-026 — A raw stream kind for uncalibrated skin temperature

Status: accepted.

## Context

WHOOP 4.0's v24 and v25 records carry a thermistor register at body offset 65. The connector emitted
it as `skin-temp` in `degrees-celsius` after multiplying the raw `u16` by the stream's fixed-point
scale, which produced a fixture asserting **861 °C** and passing. Nothing downstream could tell that
number from a real temperature.

`docs/protocol/whoop.md` already records that 4.0 publishes no calibrated temperature — only the raw
register — and the oracle applies a ×0.04 scale gated to a 20–45 °C plausibility window, which is a
derived estimate rather than a device claim.

`StreamKind::SkinTemp` means degrees Celsius. There is no existing raw-counts kind that means
temperature: `Spo2Raw`, `RespRaw`, `OpticalRaw`, and `Ppg` are all optical.

## Decision

Add `StreamKind::SkinTempRaw`, unit `counts`. WHOOP 4.0 emits `skin-temp-raw`; the value is the
register readout, unscaled and unlabelled as a temperature. `SkinTemp` keeps its meaning and is
reserved for a device that publishes calibrated degrees.

Deriving Celsius from the raw counts is analytics, not decode. If it is ever admitted it goes through
ADR-009 with its own fixture and a stated plausibility gate — not into a connector.

## Consequences

The 4.0 records stop claiming a temperature they never carried, and the 861 °C fixture is regenerated
in counts. This is an additive `mav-model` change: no serialized name or existing variant changes, so
stored samples and every existing fixture are unaffected. Any consumer that wants 4.0 temperature now
sees an explicitly raw stream and has to decide deliberately what to do with it, which is the point.
