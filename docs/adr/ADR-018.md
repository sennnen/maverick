# ADR-018 — Connector runtime errors own codes 11000–11999

Status: accepted.

## Context

ADR-017 makes connector artifacts, trust records, WebAssembly, and emitted actions untrusted inputs.
Their failures must reach the durable journal and FFI as stable `MavError` values. Reusing Decode,
Transport, FFI, or Internal would misstate ownership: these failures happen before device bytes enter
the pipeline and often before a connector instance exists.

`mav-model::Category` is frozen. Adding a category and changing its code mapping therefore requires
an ADR before WC-P2 edits that crate.

## Decision

Add `Category::Connector`, serialized as `connector`, and assign it codes 11000–11999. Codes are
append-only under the same catalogue synchronization as every existing category. `INTERNAL_INVARIANT`
remains 10000; unassigned values outside named ranges remain Internal.

WC-P2 allocates artifact and trust failures in this range. Later connector runtime, lifecycle,
limits, state, registry, and revocation packets append within it rather than borrowing another
layer's category. `mav-connector-abi` remains independent of `mav-model`; `mav-connector-runtime`
maps its closed wire errors into these journal-facing codes.

## Consequences

Diagnostics can distinguish hostile connector input from device transport, health-data decode, app
FFI misuse, and core invariant failures. Adding the serialized enum variant is a frozen-interface
change, but no existing serialized name or numeric code changes.
