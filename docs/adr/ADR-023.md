# ADR-023 — A snapshot failure is not an empty snapshot

Status: accepted.

## Context

`mav_snapshot` returns a packed pointer/length. The SDK returned `0` when the guest's `snapshot()`
failed, and the runtime read `0` as a legally empty snapshot and returned `Ok(Vec::new())`.

So a connector that could not serialise its state told the host it had none, and the host persisted
that as the session's state. On the next resume the connector restored from nothing: history
cursors, subscription bits, and configuration progress all silently reset. Nothing was logged,
because from the host's side nothing had gone wrong.

This is the no-silent-drops rule broken at the ABI, and it was invisible precisely because the
failure path and the empty path were the same value.

## Decision

`ffi_snapshot` returns **-1** when the guest's `snapshot()` returns an error. Zero keeps its meaning:
a legally empty snapshot, which is what a connector with no state to save returns. The runtime maps
-1 to `CONNECTOR_RUNTIME_SNAPSHOT_FAILED` (11062) and fails the instance.

Any negative value is treated as the failure sentinel: a packed pointer/length is a non-negative
value by construction, so the sign bit is free and reserving all of it leaves room for future codes
without another ABI decision.

The SDK goes to 0.1.1. The template and both connectors move their exact pin, and
`tools/validate.py` enforces the new one.

## Consequences

A connector that cannot snapshot now fails loudly instead of quietly discarding a session's state.
The ABI version is unchanged — the return type and the meaning of every previously-valid value are
unchanged — so an artifact built against 0.1.0 still runs; it simply keeps the old behaviour of
reporting failure as emptiness, which is why the pin is exact and validation enforces it.
