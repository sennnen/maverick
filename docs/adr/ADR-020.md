# ADR-020 — Frame reassembly lives in the connector

Status: accepted.

## Context

BLE delivers notifications, not frames. An ATT payload is bounded by the negotiated MTU — 20 bytes
before negotiation, typically 244 after — while a WHOOP frame is bounded by the record it carries.
A gen5 v20 optical buffer is roughly 2,140 bytes and a v21 deep IMU buffer roughly 1,240. Both cross
several notifications. The strap also packs short frames together when they are ready in the same
interval, so one notification can carry two whole frames.

Until this ADR the WHOOP connectors called `decode_frame` once per notification, and `decode_frame`
requires the buffer to hold exactly one complete frame. Every deep buffer was therefore rejected as
`Truncated` and reported as a malformed frame, and the second of two packed frames was never seen.

`mav-frame::Reassembler` already exists in the core, but it is host-side. ADR-016 and ADR-017 put
device knowledge inside the signed Wasm guest, which cannot reach a host crate; the frame layout that
tells reassembly where a frame ends is device knowledge.

## Decision

Reassembly is a connector responsibility, implemented in `whoop-protocol` as `Deframer` and held one
instance per notify characteristic. It buffers fragments, reads the declared length from the
generation's header, emits each complete frame, and resynchronises on the start byte — never on a
delimiter, because payload bytes are freely `0xaa`. A frame whose CRC fails is returned as an error
rather than dropped, and the declared length is still consumed so the stream behind it stays aligned.

Deframer state is deliberately excluded from the connector snapshot. A partial frame is meaningful
only within one link; resuming it across a reconnect would splice the tail of an abandoned frame onto
the head of a new one. Connectors therefore call `reset()` on activate, resume, disconnect, and state
restore, and the snapshot length is unchanged by this ADR.

`mav-frame::Reassembler` keeps its place for host-side transports that are not connector-mediated.

## Consequences

Deep buffers decode for the first time, and the frames packed behind a frame are no longer lost. A
truncated notification is no longer reported as malformed — it is simply incomplete, and the
connectors' `malformed-frame` fixtures now carry a whole frame with a broken CRC, which is the case
that genuinely cannot be recovered. Per-characteristic buffering costs at most one frame of memory
per channel, bounded by the 8,192-byte frame ceiling the protocol crate already enforces.
