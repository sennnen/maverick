# ADR-006: ML inference stays native

## Context

If Maverick ever ships a learned model, something has to run it. The candidates are a Rust
inference stack inside the core, or the platform runtimes: CoreML on iOS, TFLite on Android. The
platform runtimes are what the vendors accelerate and maintain; models are compiled per-runtime and
do not port across. A Rust stack would forfeit hardware acceleration, add a heavy dependency, and
buy nothing, since determinism is only needed in preprocessing, which Rust already owns. It also
matters that no model currently exists: neither prior codebase shipped one, and today's analytics
are deterministic DSP and statistics.

## Decision

Inference is native, behind a tensor-in, tensor-out boundary. Rust owns all preprocessing
(resample, filter, FFT, spectrogram, feature extraction), pure and golden-vector tested. Each model
gets a documented contract (input shape, dtype, normalisation, output interpretation, confidence
semantics, file hash, version) before it ships. Predictions re-enter the pipeline as first-class
features with provenance. No CoreML or TFLite dependency is added until a real model with a golden
vector exists.

## Consequences

The error-prone part of any ML path, the preprocessing, lives in shared fixture-tested code, and
the per-platform surface is a single call. The boundary is designed now while it is cheap, but
carries no dependency cost while it is unused. The cost is a second native seam alongside the radio
and the acceptance that inference itself is not bit-identical across platforms; the contract and
golden vectors bound how much that can matter.
