# ADR-017 — Runtime-loaded WebAssembly connectors

Status: accepted for implementation planning; runtime implementation has not started.

## Context

ADR-007 split a connector into declarative data and a boxed `DeviceCodec`. ADR-011 moved
manifests to `sennnen/maverick-connectors`. ADR-016 then placed irreducible device logic in
compiled crates under `core/connectors/` and registered those crates from `mav-ffi` and
`mav-replay`.

That design isolates device logic from core crates, but it is still a bundled-driver design. A new
codec changes the Cargo workspace, both edge crates, the application binary, and both app-store
artifacts. It cannot meet the product requirement that one connector artifact install on either
mobile platform without rebuilding Maverick.

The protocol audit at `tanarchytan/whoop-rs` commit
`375af9c8739304c105f9c8116b0038fe338e8488` also shows that decode-only is the wrong ABI boundary.
WHOOP needs generation-specific discovery, characteristic mapping, bond order, confirmed writes,
command construction, history cursors, persist-before-ack ordering, inactivity timers, reconnect
policy, and protocol-local state. Those facts must not migrate into a supposedly generic core state
machine.

Native dynamic libraries cannot provide one safe cross-platform artifact, and downloaded native
code is not acceptable on iOS. JavaScript would add a second language and runtime without improving
the boundary. A no-JIT WebAssembly interpreter can run identical portable bytes inside the shared
Rust core, subject to deterministic resource limits.

Apple App Review Guideline 2.5.2 currently prohibits downloaded code that introduces or changes app
features. Interpreted WebAssembly does not remove that review risk. The architecture therefore
separates artifact format from platform trust policy: iOS may be restricted to reviewed official
connectors, and remote connector distribution is a release gate requiring explicit App Review
evidence. See [Apple's current guideline](https://developer.apple.com/app-store/review/guidelines/).

## Decision

A connector is one `.mavconn` file that remains a valid WebAssembly module. It carries deterministic
metadata in uniquely named custom sections, including `mav:manifest`, `mav:abi`, `mav:fixtures`, and
`mav:signature`. The host parses, bounds, validates, and verifies those sections before module
instantiation. Duplicate required sections are invalid.

Connector logic executes in a pure Rust interpreter with no JIT. `wasmi` is the initial candidate,
not a permanent dependency choice: packet WC-P0 must prove iOS and Android builds, deterministic
fuel exhaustion, memory limits, malformed-module handling, and representative throughput before
the dependency lands. Wasmi exposes fuel, module limits, memory limits, and custom-section access;
the prototype must confirm their behaviour in Maverick rather than relying on API shape alone.

The ABI is a versioned event-and-action protocol:

1. Core sends one normalized lifecycle or transport event encoded as deterministic CBOR.
2. Connector updates only its private instance state.
3. Connector returns a bounded ordered list of declarative actions.
4. Core validates every action against the signed manifest and current lifecycle state.
5. Core executes allowed transport or persistence work in order.
6. Each result returns as another normalized event.

ABI v1 exposes no host imports. The module receives bounded byte messages through fixed allocation,
deallocation, initialization, event, and snapshot exports. It has no filesystem, network, native
API, BLE object, process, thread, wall-clock, or random source. Timers are opaque host-owned tokens.
Connector state persists only through scoped persistence actions executed by core.

Core owns installation, signature and trust policy, revocation, resource accounting, generic BLE
execution, connector-scoped storage, normalized health-data admission, diagnostics, activation,
updates, rollback, and removal. Native shells acquire bytes and execute validated generic transport
actions. Connectors own all device knowledge and protocol state, including UUIDs, packet formats,
commands, handshakes, acknowledgements, generation differences, and firmware workarounds.

WHOOP 4.0 and WHOOP 5.0/MG become separate `.mavconn` artifacts built with the same public SDK and
installed by the same path as third-party connectors. Native and WebAssembly paths may coexist only
for measured parity. The compiled `mav-connector-whoop` crate, codec factory registry, explicit edge
registration, `codec` manifest field, and legacy folder-manifest installation path are deleted in
the packet that switches the active path.

Connector signing is separate from app signing. V1 uses Ed25519 publisher keys and SHA-256 artifact
digests. The exact canonical representation, trust rules, and rotation/revocation model are frozen
in [connectors.md](../connectors.md). The Android release JKS is neither read nor reused.

## Consequences

Adding a device no longer changes Maverick or republishes either app. One artifact and execution
path serve iOS, Android, replay, validation, and tests. The ABI must be narrower and more rigorously
versioned than the current Rust trait because untrusted code crosses it.

Interpreter overhead, binary size, mobile memory pressure, ABI serialization cost, and App Review
acceptance become explicit gates. A failed prototype stops implementation before product code
depends on the runtime. iOS policy may allow fewer publishers than Android without forking the
artifact format.

This ADR supersedes ADR-007's in-process trait as the distributable connector boundary, ADR-011's
folder-manifest import model, and ADR-016's compiled codec crates and edge registration. Their
historical rationale remains useful during migration.
