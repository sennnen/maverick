# ADR-007: Declarative manifests plus a boxed DeviceCodec

## Context

The clean version of device support is a purely declarative manifest: every device described
entirely as data, no device-specific code anywhere. The surveyed codebases show the clean version
does not survive contact with real hardware. Handshakes are stateful, some decodes need memory
across frames, and the WHOOP 4.0 skin-temperature scale is not a constant at all but a per-device
anchor learned from that specific strap's worn-band median. A static file cannot carry a value that
does not exist until the device has been worn.

## Decision

A connector is a manifest.json holding everything static (identity, GATT UUIDs, frame parameters,
packet map, field layouts, unit conversions, record versions, sensor configs) plus, only when the
device needs it, a small DeviceCodec for the logic data cannot express. The codec is boxed by its
interface: it receives bytes, its own manifest, and a per-device key-value store, and it cannot
reach storage, network, analytics, or other devices. Adding a device is one manifest plus at most
one codec, with zero core edits.

## Consequences

The bulk of device knowledge stays reviewable data, diffable without reading Rust, while the
irreducibly stateful residue has a contained home rather than leaking into the pipeline as
special cases. A broken codec can at worst emit wrong samples for its own device, which quality
scoring, plausibility gates, and fixtures catch; it cannot corrupt storage or another strap's
state. The cost is policing the line: anything expressible as manifest data must go in the
manifest, and the mock connector exists to prove the contract holds before more devices depend
on it.
